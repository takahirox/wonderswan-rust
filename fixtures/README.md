# Original hardware compatibility probes

All source (`compat.asm`, `gdma.asm`, `sound.asm`, `internal-eeprom.asm`, `build.py`), generated cartridges in `generated/`,
and test graphics/sound data in this directory are original work authored for
this repository for Issues #11, #13, #19 and #21, dedicated to the public domain under **CC0-1.0**
([full license](LICENSE)). No downloaded ROM, BIOS, emulator implementation,
game asset, font, or audio recording was used. Graphics are constant tile planes
or packed nibbles; sound is a square wavetable generated by cartridge instructions.
The native bank vectors in `ws-core` tests are also generated directly in memory.

Rebuild with Python 3 and NASM (no third-party libraries):

```sh
python3 fixtures/build.py
python3 fixtures/build.py --check
cargo test --workspace --locked
```

Each image is 128 KiB with a reset far jump, typed header and additive checksum.
The source is assembled for F000:0000 in the last bank. The leading bank contains
an original constant marker. Hardware probes are deliberately small programs,
not compatibility patches or commercial-game substitutes.

| Cartridge | Save | Mapper interface | Color rendering |
| --- | --- | --- | --- |
| `sram32-common.ws` | 32 KiB SRAM, including 8000 mirror | Common C0–C3 | 4bpp planar |
| `sram128-2003.ws` | 128 KiB SRAM, independent banks 0/1 | Bandai 2003, GPO, self-flash read mapping, RTC absence | 4bpp planar |
| `eeprom128.ws` | 128-byte EEPROM | Common | 4bpp planar |
| `eeprom1024.ws` | 1024-byte EEPROM | Bandai 2003 extensions | 4bpp planar |
| `eeprom2048-packed.ws` | 2048-byte EEPROM | Bandai 2003 extensions | 4bpp packed |
| `gdma.ws` | None | Common, fast 16-bit ROM | Green screen on success; red on assertion failure |

The five save probes initialize their own stack/segments, increment save word/byte
zero (FF/FFFF means uninitialized), execute IMUL/ADC/ROL, far CALL/RETF and INT/IRET,
check a mapped ROM bank, install line/VBlank/HBlank-timer handlers, read the
keypad after HLT wake-up, and program all four sound channels. SRAM bank 1 on
the 128 KiB image contains the boot count plus 64. EEPROM probes use WEN, READ,
WRITE and controller busy polling; the protocol unit tests additionally exercise
write protection, ERASE, WDS, WRAL/ERAL, abort, separate buffers and all sizes.

On color models, (0,0) is green Screen 1, (9,9) red windowed Screen 2, and (16,16)
a blue high-priority sprite from the VBlank-latched table. The source checks the
model port and uses a monochrome fallback on WonderSwan, so all probes also run
there. Native framebuffer tests separately generate 2bpp color, tile-bank, palette,
flip/scroll, sprite order/window/limit and transparency vectors from memory.

RAM observations for native tests/Debug tooling:

| Address | Observation |
| --- | --- |
| 0400 | Save boot count |
| 0402 | Hardware interrupt count |
| 0404 | Selected X keypad row (22 when Right is held) |
| 0406 | Arithmetic result (10) |
| 0408 | Mapped ROM bank marker (31 hex) |
| 040A–040C | 2003 GPO (5), self-map marker (31), absent RTC (FF) |
| 040D | SRAM32 mirror read |
| 040E | Software interrupt marker (1234 hex) |

For browser checks, build Wasm/frontend, start Vite preview, then run
`npm run test:compat` from `web` (set `WS_PREVIEW_URL` if needed). The suite selects
these files locally; it does not fetch/upload ROM or save data. To try manually,
choose **Load ROM** and select a generated image; sound defaults to on after
this interaction. Use **Enable audio** if browser policy requires a retry, and
adjust **Volume** or **Mute**.
Reload and reselect the same cartridge to continue its saved boot count; ROMs
are deliberately not cached automatically. Native tests check save bytes; the
browser suite checks the actual localStorage slots and Web Audio buffers.

The separate `gdma.asm` probe uses original constants 1122/3344/5566, byte `OUT`
to program aligned/masked source, destination, length and control registers, and
byte `IN` to assert all eight register values after each copy. CPU instructions
compare all three RAM words after forward and reverse transfers. A successful
Color/Crystal run stores 600D at 0400, 1 at 0402/0404, and draws green; failure
stores 0BAD and draws red. Mono stores 4D4F (skipped) and halts without accessing
GDMA. The native integration test checks these markers, actual RAM and pixels
on all three models. The browser compatibility suite loads this exact ROM through
the existing file picker and checks green output without execution errors on
Color/Crystal. The fixture is freely redistributable under the same CC0 license.

## SDMA and Hyper Voice probes (Issue #19)

`python3 fixtures/build.py` assembles `sound.asm` three times with `SOUND_PATH`
0/1/2. No external waveform files are needed. All three 128 KiB cartridges and
their source/data are CC0-1.0. They initialize stack/segments, detect the console
through A0, and skip color-only sound hardware on mono (marker 0400 = 4D4F,
0402 = 0; silence). On Color/Crystal they draw green and store 0400 = 600D,
0402 = 1 when their register assertions succeed; red/0BAD means failure.

| Cartridge | CPU programming and expected PCM at 24 kHz |
| --- | --- |
| `sound-channel2.ws` | Finite two-byte SDMA, check next source 1002/length 0/last 89=E0, then repeat 32 RAM bytes (sixteen 20, sixteen E0) to Channel 2. Voice volume full both sides. Headphone floats 0.03125 and 0.21875, equal stereo, a 750 Hz square. |
| `sound-hyper.ws` | Same finite/repeat transfers targeting Hyper Voice, signed shift 1, mono-both layout. Finite input latches end E0/E0. Legacy channels off; headphone floats −0.125/+0.125, equal stereo. |
| `sound-direct.ws` | CPU writes to 69 assert alternating +4096/−4096 outputs even in mono-both DMA layout, then checks direct 16-bit outputs. Loops between 16-bit outputs ±8192 and converted 8-bit outputs ±4096, opposite stereo except brief transitions between separate OUT instructions. Headphone floats ±0.25 and ±0.125. No SDMA enabled. |

The two SDMA probes also check high-nibble masks and unused 4D/51 ports, and halt
the CPU while repeat playback continues. These are actual V30MZ instructions,
not host-side port injection. Restart regenerates the same first-frame PCM.
Native `crates/ws-core/tests/sound.rs` checks markers, pixels, exact buffers,
all three models, silence, drain and restart. `npm run test:compat` loads these
same files through the production Wasm player, inspects real Web Audio sample
buffers and verifies gain, mute, pause/resume, visibility, restart and model
selection. The native vectors additionally cover all SDMA and Hyper Voice rates,
bus timing and interactions, signed extension and wrapping mix arithmetic.
See [hardware coverage and limitations](../docs/hardware-subset.md#sound-dma-semantics-and-shared-timing)
and [recorded validation](../docs/issue-19-validation.md).

## Internal console EEPROM probes (Issue #21)

`internal-eeprom.asm` is original CC0 source assembled into two 128 KiB images:
`internal-eeprom.ws` requests writable settings through header byte 9 bit 7;
`internal-eeprom-protected.ws` requests the normal protected handoff. Both declare
32 KiB cartridge SRAM but never write it, demonstrating independent console data.
The programs run on all three models, starting with six-bit mono commands, then
using ten-bit Color commands on Color/Crystal. They initialize their own segments,
stack, tile data and display. No firmware, title detection or host port injection
is involved. Build/check commands above include both images.

Each reads the owner/settings word at byte 60, increments the shared word at 00,
polls READY and READ DONE, checks separate read/write buffers, WDS/WEN and the
header exception, restores the settings word, sets protection twice through word
OUT BE (including nonzero reserved BF), writes the boundary word at 5E and checks
that writes at 60 fail. Color/Crystal additionally preserve the final physical
word across protected writes and mono/Color transitions. A self-checked pass
stores 600D at RAM 0400 and draws green (Color/Crystal) or gray 170 (Mono);
failure stores 0BAD and draws red or gray 187. RAM 0402 is the shared counter,
0406 the original settings word, and 0408 the last Color word.

The native integration test imports distinct settings/final-word markers, checks
these actual CPU results, settings preservation, independent cartridge saves,
restart, cross-cartridge sharing, export/reimport into a new machine, and all
three model records. Browser compatibility checks load the exact same images in
the production Wasm player and inspect their pass pixels and localStorage bytes.
The browser suite disables the one-second persistence timer in its isolated
console context to prove lifecycle/model flushes themselves retain data; it also
checks reload/reopen, malformed/size-mismatched records, denied console reads and
full console storage with independently working cartridge saves. Injected storage
failures are synthetic. Neither fixture is a physical-console validation result.
