# Beacon Trail

An original, silent, monochrome WonderSwan game created for this repository in
2026 with OpenAI Codex assistance. Move the hollow square onto three diamond
beacons, one at a time. The cartridge draws the score and an **ALL FOUND!** message
when complete. Arrow keys / WASD move in the browser; Enter maps to cartridge
Start and restarts. Held directions repeat every eight display frames.

All files in this directory and `web/public/demo/`, including the compiled ROM,
source, build scripts, lettering and geometric graphics, are dedicated under
**CC0-1.0**. See [LICENSE](LICENSE) and the deployed [notice](../web/public/demo/NOTICE.txt).
No third-party game assets, fonts, commercial ROMs, BIOS dumps, or firmware were
used. The license legal text comes from Creative Commons; NASM is an external
build tool and is not bundled into the cartridge.

## Rebuild

Install Python 3 and [NASM](https://www.nasm.us/) (validated with Python 3.13 and
NASM 3.02). For example, `brew install nasm` on macOS or
`sudo apt-get install nasm` on Debian/Ubuntu. From the repository root:

```sh
python3 demo/build.py
python3 demo/build.py --check
cargo test --workspace --locked
```

The assembler consumes [game.asm](game.asm); [graphics.py](graphics.py) produces
original 2bpp tiles in a temporary directory. The builder pads the first bank,
places executable code and tile data in the final 64 KiB bank, adds the real
WonderSwan footer and its additive checksum, then writes the deterministic
128 KiB `web/public/demo/beacon-trail.ws`. There are no timestamps, external
assets or network requests in the build. `--check` compares every generated byte
with the committed asset and fails on a difference. The deployed site uses this
same file, and native integration tests include it directly.

The game is a standalone cartridge program, not a DOS executable: entry is a far
jump at the final sixteen bytes into F000:0000. It initializes its own segments,
stack, all 16 KiB of common RAM, display/palette/scroll registers, and tile data.
It polls the scanline register for VBlank and reads the real keypad matrix port.
It never calls firmware, enables interrupts, or requires color-only hardware.
See [hardware scope](../docs/hardware-subset.md). It has not been tested on a
physical console; actual hardware behavior remains optional validation.

For deterministic testing/debugging, the ROM owns these ordinary RAM words:
`0400` X, `0402` Y, `0404` collected count, `0406` movement cooldown,
`0408` target X, `040A` target Y. The emulator does not interpret these locations.
The initial square is at tile (3,8), with targets (9,8), (9,5), then (18,5).
A solution is Right ×6, Up ×3, Right ×9. Game bounds are X=2..25, Y=4..14.
